# 发布指南

怎样从源码构建出一个能用的绿色版，以及怎样打包和发布。只是使用软件的话看 [README](../README.md) 就够了；想了解代码看[技术说明](技术说明.md)。

## 1. 环境

- Windows 10 / 11
- Node.js 20 或更高版本
- pnpm
- Rust，使用 MSVC 工具链 `stable-x86_64-pc-windows-msvc`（GNU 工具链不能用于 Tauri）
- Visual Studio Build Tools 2022，包含 C++ 生成工具
- WebView2 Runtime
- 发布到 GitHub 时另外需要 [GitHub CLI](https://cli.github.com/)（`gh`）

## 2. 构建

在项目根目录执行：

```powershell
pnpm install
pnpm build
cargo +stable-x86_64-pc-windows-msvc build --manifest-path src-tauri/Cargo.toml --release --features tauri/custom-protocol
```

几点说明：

- `--features tauri/custom-protocol` 不能省。缺少它编出来的是开发模式的程序，不会内嵌 `dist/`，启动后会去连接本地开发服务器。
- 项目没有 `tsconfig.json`，类型检查用显式参数运行：

  ```powershell
  node node_modules/typescript/bin/tsc --noEmit --strict --target ES2022 --module ESNext --moduleResolution bundler --skipLibCheck --lib ES2022,DOM,DOM.Iterable src/main.ts src/gcj02.ts src/vite-env.d.ts
  ```

- 产物是 `src-tauri/target/release/photo-gps-manager.exe`。

## 3. 组装绿色版目录

编译出来的 exe 自己跑不起来，旁边必须有 ExifTool 和 VC++ 运行库。目录结构如下：

```text
green-release/
├─ GeoTagStudio.exe        # 由 photo-gps-manager.exe 复制并改名
├─ exiftool.exe            # ExifTool 启动器（官网 Windows 包里的 exiftool(-k).exe，改名而来）
├─ exiftool_files/         # ExifTool 本体和 Perl 运行环境，与 exiftool.exe 缺一不可
├─ concrt140.dll           # 以下 10 个是 VC++ 运行库
├─ msvcp140.dll
├─ msvcp140_1.dll
├─ msvcp140_2.dll
├─ msvcp140_atomic_wait.dll
├─ msvcp140_codecvt_ids.dll
├─ vccorlib140.dll
├─ vcruntime140.dll
├─ vcruntime140_1.dll
└─ vcruntime140_threads.dll
```

程序运行后还会在同目录生成 `data` 文件夹，里面是使用者自己的高德 Key 和处理记录。**`data` 不打包，也不提交。**

`green-release/` 整个目录都在 `.gitignore` 里，程序和 ExifTool 都不进版本库，只以压缩包的形式发布到 Releases 页面。

### ExifTool

1. 从 ExifTool 官网 <https://exiftool.org/> 下载 Windows 版压缩包（页面上的 “Windows Executable”），例如 `exiftool-13.64_64.zip`
2. 解压后把 `exiftool(-k).exe` 改名为 `exiftool.exe`
3. 把 `exiftool.exe` 和 `exiftool_files` 文件夹一起放进 `green-release/`

注意事项：

- `exiftool.exe` 只有约 58 KB，它只是一个启动器，ExifTool 本体在 `exiftool_files` 里（约 500 个文件、35 MB）。两者缺一不可，少了文件夹会报 `Could not find ...\exiftool_files\perl5*.dll`
- `exiftool(-k).exe` 运行结束时会停下来等待按回车，所以必须改名
- 整个文件夹原样保留，不要删改其中的 `LICENSE`、`Licenses_Strawberry_Perl.zip` 等许可文件，见[第三方组件声明](../THIRD-PARTY-NOTICES.md)
- 程序优先查找自身目录下的 `exiftool.exe`，其次才是当前工作目录

### VC++ 运行库

上面 10 个 DLL 来自 Microsoft Visual C++ 2015-2022 Redistributable（64 位）。取得办法：先在本机安装微软官网的 [VC++ 运行库最新版](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist)（`vc_redist.x64.exe`），然后从 `C:\Windows\System32` 里把这 10 个文件复制到 `green-release/`。

不要省掉它们：在没有装过 VC++ 运行库的电脑上，只有 exe 会启动失败。

## 4. 打包

确认 `green-release/GeoTagStudio.exe` 是刚构建出来的版本，然后在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\package-release.ps1
```

脚本会检查必需文件是否齐全，把程序、运行库和 ExifTool 连同三份说明文件打成 `release\GeoTagStudio-<版本号>-win-x64.zip`。版本号读自 `src-tauri/tauri.conf.json`，也可以用 `-Version` 指定。

压缩包里有一个同名的顶层文件夹，解压后不会散落一地。`green-release\data` 永远不会被放进去。

放进压缩包的三份文件：

| 压缩包里的名字 | 来源 |
| --- | --- |
| `README.txt` | `packaging/README.txt`，给不看 GitHub 的用户看的纯文本说明 |
| `LICENSE.txt` | 项目许可证全文 |
| `THIRD-PARTY-NOTICES.txt` | 第三方组件声明 |

## 5. 发布到 GitHub

1. **改版本号**。三个文件里的 `version` 要一致：`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`（`src-tauri/Cargo.lock` 会在构建时自动更新）。README 的下载步骤写的是 `<版本号>` 占位，不用改。
2. **按第 2 节重新构建**，把新的 exe 放进 `green-release/`，实际运行一次确认正常。
3. **提交源码并推送**：

   ```powershell
   git add -A
   git commit -m "Release v0.1.0"
   git push
   ```

4. **打包**（第 4 节），确认压缩包里没有 `data` 文件夹。
5. **打标签并上传**：

   ```powershell
   git tag v0.1.0
   git push origin v0.1.0
   gh release create v0.1.0 release\GeoTagStudio-0.1.0-win-x64.zip --title "GeoTag Studio v0.1.0" --notes-file release\release-notes.md
   ```

   `release\release-notes.md` 是自己写的更新说明。`release\` 在 `.gitignore` 里，不会被提交。

发布前对照检查：

- [ ] 压缩包里没有 `data` 文件夹
- [ ] 源码、文档和压缩包里没有任何高德 Key 或安全密钥
- [ ] `THIRD-PARTY-NOTICES.md` 里的 ExifTool 版本号与压缩包里的一致
- [ ] 在一台没装过开发环境的电脑上（或者把 `green-release` 复制到别的目录、删掉 `data` 后）能正常启动、搜索并写入

## 6. 绿色版运行说明

- JPG、JPEG、PNG、TIFF、HEIC、RAW：写入 EXIF GPS，默认先把原文件备份为 `xxx.bak`。已用 Sony ARW、JPEG、iPhone HEIC 实测
- 已有的 `.bak` 不会被覆盖，始终是第一次写入前的原始文件
- 备份失败就不会写入；写入失败且原文件未改动时，不留备份
- 文件名可以含中文、空格、表情符号等任意字符
- MP4、MOV、M4V、MKV：保留原视频，生成同名 `.xmp`（这一步不需要 ExifTool）
- 找不到 `exiftool.exe` 或它运行失败时，照片和 RAW 会返回明确错误，不会假装成功
- 首次启动会在 exe 同目录自动创建 `data` 文件夹，请把程序放在有写入权限的目录
- exe 所在目录不可写时，会自动改用 `%LOCALAPPDATA%\com.photogps.manager`
